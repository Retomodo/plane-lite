# Deliberate deviations from the Django API

The Go server reproduces the Django backend's responses exactly, as checked by
the contract goldens. These are the known, intentional differences.

| Area | Django | Go | Why |
|---|---|---|---|
| `GET /api/instances/` caching | Response cached in Redis for 2 h, so `workspaces_exist` stays stale after the first workspace is created | Computed per request | Stale cache was a bug; the query is cheap |
| `ENABLE_SIGNUP` default | `"0"` for the instance config the web app reads, `"1"` for the actual sign-up check | One setting, default `1` | One knob, one meaning |
| God-mode admin | Instance must be set up through the admin app before anyone can sign in | Instance registered and marked set up at boot; all config comes from env vars | Admin app dropped |
| Accepted project invites on login | `ProjectMember` rows created without `project_id`, which violates NOT NULL and fails the login | Rows include `project_id` | Bug fix |
| Login redirect | Computes `get_redirection_path()` ("onboarding", a slug, ...) and then discards it because it lacks a leading `/` | Skips the computation; same redirect (app root, or `next_path`) | Same behaviour, no wasted queries |
| Session payload | Django's signed, compressed `session_data` | Plain JSON in the same `sessions` table | Clean cutover; sessions don't need to be readable by Django. Existing sessions are invalidated on migration (users sign in again) |
| Background jobs | Celery on RabbitMQ, separate worker and beat processes; a failed task is logged and dropped | River queue in Postgres, worked inside the server process; email jobs retry up to 3 times | No broker to run; jobs survive Redis eviction |
| Malformed JSON bodies | 400 `{"detail": "JSON parse error - <Python json message>"}` | Same status and prefix; the message after the dash is Go's | Not worth reimplementing Python's parser messages |
| Lone UTF-16 surrogates in JSON (`"\ud800"`) | Accepted by the parser; CharFields answer "Surrogate characters are not allowed" | Rejected as malformed JSON (400) | Go strings can't hold lone surrogates |
| `/api/users/me/accounts/` | Lists the user's OAuth accounts | Always `[]`; `/accounts/<id>/` is always 404 | OAuth is cut, so no accounts can exist |
| Workspace creation | Enqueues `workspace_seed`: a bot user and a demo project with states, labels, issues, cycles, modules, pages and views | Creates only the workspace and the creator's membership (the contract reference has the task disabled) | Demo data is clutter for a team that brings its own work |
| Unused workspace endpoints | `W/workspace-themes/…` and `/api/users/last-visited-workspace/` answer (the latter with a 500 in the recorded reference) | 404 | No caller in the web or live apps |
| Project payloads and CUT features | `W/projects/` counts pending intake issues as `intake_count`; project details carry the deploy-board `anchor`; turning `inbox_view` on creates a default Intake | `intake_count` is always `0` and `anchor` always `null`; the `intake_view` flag is stored but no Intake row is created | Intake and publishing are cut |
| Project activity tasks | Project create, update and delete enqueue `model_activity` / `webhook_activity` | Not run | They only feed webhooks, which are cut |
| Unused project endpoints | `PUT W/projects/<pk>/`, `DELETE W/project-identifiers/`, `GET /api/users/me/workspaces/<slug>/projects/invitations/` answer; so do `P/invitations/…`, `P/join/<pk>/`, `P/project-views/` and `P/preferences/member/<id>/` | 405 for the first three (their URLs have other methods), 404 for the rest | No caller in the web or live apps. Project invitations can't be created anyway (Django's create crashes); people join projects through workspace invites or the project's member list |
| `GET W/labels/` caching | Cached per user in Redis for 2 h. Creating a label clears it; editing or deleting one, archiving a project or changing members does not, so the list goes stale | Computed per request | Stale cache was a bug; the query is cheap |
| `GET W/estimates/` caching | Cached per user and full path in Redis for 2 h. Estimate writes invalidate a key without the user, which never matches, so the list stays stale | Computed per request | Stale cache was a bug; the query is cheap. With this, Go has no Redis response caches and no `invalidate_cache` calls |
| `GET /api/timezones/` caching | `cache_page`: the page is stored in Redis for 2 h per full URL, and replayed with an `Age` header | Built per request with the same `Expires` and `Cache-Control: max-age=7200`; no `Age` | The list is static and cheap. A Redis entry per Host and query string is unbounded growth in a shared Redis |
| `GET P/issues/<id>/history/` compression | Wrapped in `gzip_page`, so it is gzipped when the client accepts it | Not compressed; the body is identical | Compression belongs in the reverse proxy |
| Link title crawler on real pages | `crawl_work_item_link_title` parses with BeautifulSoup, reads the whole response, and has an "Unexpected error" metadata branch | `x/net/html`, at most 10 MiB read, no such branch. Same SSRF guard, timeouts and metadata shape | Malformed markup may yield a different title; the goldens only cover URLs the guard or DNS rejects |
| Live server URL | `LIVE_URL` = `LIVE_BASE_URL` joined with `LIVE_BASE_PATH` (default `/live/`) | `LIVE_BASE_URL`'s scheme and host plus a fixed `/live/` path | The base path is never changed in practice; one less setting |
| Page HTML text extraction | Python's `html.parser` through BeautifulSoup | A Go port of both (`page_html.go`), checked against fixtures from Python; lowercasing skips Python's final-sigma rule and one CDATA end-tag match is ASCII-only | Editor HTML never hits these cases |
| Unused label endpoints | `GET`/`PUT P/issue-labels/<pk>/` and `POST P/bulk-create-labels/` answer | 405 for the first two (the URL has PATCH and DELETE), 404 for bulk create | No caller in the web or live apps |
| HTML sanitizer | nh3 (Rust ammonia on html5ever) | A Go port on a vendored copy of `x/net/html`, checked against nh3 output for the editor's markup, adversarial cases and 3,184 random fragments | No Rust in the build. 18 random tag-soup fragments (misnested formatting elements inside tables and `<select>`) still clean differently; editor output and every hand-written case match |
| Issue `?expand=` | Any relation `IssueDetailSerializer` can expand | `issue_reactions`, `issue_attachments`, `issue_link` and `parent`, the ones the web asks for; other names are ignored | No other caller |
| Issue origin cache | `issue_activity` stores the request's origin in Redis per issue, for links in notification emails | Not written; emails build links from the configured app URL | The origin is configuration, not per-request state |
| Unused issue endpoints | `GET P/issues-detail/`, `GET P/v2/issues/`, `PUT P/issues/<pk>/` and `GET P/deleted-issues/` answer | 405 for the `PUT` (the URL has other methods), 404 for the rest | No caller: the web only asks for `issues-detail` with `expand=issue_relation`, which it never sends; the other service functions are dead |
| Unused issue sub-resource endpoints | `GET P/issues/<id>/comments/`, `GET`/`PUT P/issues/<id>/comments/<pk>/`, the `P/issues/<id>/issue-subscribers/…` routes, `GET`/`PUT P/issues/<id>/issue-links/<pk>/`, `P/issues/<id>/versions/` and the v1 `P/issues/<id>/issue-attachments/…` routes answer | 405 where the URL has other methods, 404 otherwise | No caller in the web or live apps |
| Unused notification endpoint | `DELETE W/users/notifications/<pk>/` soft-deletes and answers 204 | 405 (the URL has GET and PATCH) | No caller in the web or live apps |
| Unused estimate and home endpoints | `GET P/project-estimates/`, `GET`/`PATCH P/estimates/<id>/`, `DELETE P/estimates/<id>/estimate-points/<point_id>/`, `GET W/quick-links/<pk>/`, `GET W/stickies/<pk>/`, `PATCH W/home-preferences/` (no key) and `GET W/home-preferences/<key>/` answer (the last two with a 500) | 405 (each URL has other methods), 404 for `P/project-estimates/` | No caller in the web or live apps |
| Unused saved view endpoints | `PUT P/views/<pk>/` and `PUT W/views/<pk>/` answer | 405 (the URLs have GET, PATCH and DELETE) | No caller in the web or live apps |
| Unused page endpoint | `GET P/pages-summary/` answers | 404 | No caller in the web or live apps |
| Unused cycle endpoints | `PUT P/cycles/<pk>/`, `PUT P/cycles/<id>/cycle-issues/`, `GET`/`PATCH P/cycles/<id>/cycle-issues/<issue_id>/`, `GET P/cycles/<id>/archive/` and `POST`/`DELETE` on `P/archived-cycles/…` answer | 405 (each URL has other methods) | No caller in the web or live apps |
| Unused module endpoints | `PUT P/modules/<pk>/`, the module issue list, retrieve, `PUT` and `PATCH`, module-link list, retrieve and `PUT`, `GET P/modules/<id>/archive/` and `POST`/`DELETE` on `P/archived-modules/…` answer (the last two with a 500) | 405 (each URL has other methods) | No caller in the web or live apps |
| Unused profile endpoints | `GET /api/users/me/activities/`, `GET /api/users/me/workspaces/<slug>/activity-graph/`, `…/issues-completed-graph/` and `…/dashboard/` answer | 404 | No caller in the web or live apps |
| `P/issues/list/` `?fields=` / `?expand=` | Switch the response to `IssueSerializer` with those fields and expansions | Ignored: always the plain `.values()` list | The web sends only `?issues=` |
| Unused favorite endpoints | The list `GET`s of `P/user-favorite-cycles/`, `-modules/`, `-views/` and `W/user-favorite-projects/`, `DELETE P/favorite-pages/<id>/` (204), and `GET`/`POST W/user-favorites/<id>/` plus the id-less `PATCH`/`DELETE W/user-favorites/` (a 500) answer | 405 where the URL has other methods, 404 otherwise | No caller in the web or live apps |
| Global search `intake` bucket | Searches intake issues | Always `[]` (a malformed `project_id` is still a 400) | Intake is cut |
| Scheduled jobs | Celery beat with `django_celery_beat`, separate processes | River periodic jobs in the server process, run by the leader only; a run missed while the server was down executes once at the next start | No beat or worker process to run |
| Notification digest without the origin key | Mails are silently dropped when the digest runs more than 10 minutes after the issue's last request (the Redis origin key expired); the logs stay processed and never sent | Always mails, with links built from `APP_BASE_URL` | Follows "Issue origin cache"; late runs must not lose mail |
| Notification digest send failure | Logged; the logs stay unsent forever | Retried (3 attempts); never resent once a mail has gone out | Same as the other email jobs |
| Notification digest mention HTML | BeautifulSoup re-serializes the comment fragment after replacing mentions | Mentions replaced in place, the rest kept as written | The text part is identical; HTML serialization details may differ |
| Nightly hard delete and issue activities | Hard-deleting an issue or comment that still has activities fails its deferred foreign key (DO_NOTHING), so once any such row is past the cutoff the job stops at that step every night and nothing after it is ever purged | The activities are purged with their issue or comment, and every run completes | User decision: Django's job never completes once such a row exists. Covered by the Go-only `TestScheduledHardDeleteDeviation` |
| Upload protocol | Presigned S3 POST: `upload_data.url` is the bucket and the browser posts straight to S3 | The same response shape (`upload_data: {url, fields}`, `asset_id`, `asset_url`), but `upload_data.url` is `/api/assets/v2/upload/<asset_id>/` on the API. That endpoint takes the same multipart form, checks the signed policy the way S3 would, then does a `PutObject` and answers 204, or an S3 XML error (`EntityTooLarge`, `EntityTooSmall`, `AccessDenied`, `SignatureDoesNotMatch`, `MalformedPOSTRequest`). It also checks that the policy's key belongs to that asset. | Production storage is Cloudflare R2, which has no presigned POST. The web client is unchanged: it posts `fields` + `file` to `url`. |
| Upload size and memory | S3 streams the upload | Up to 8 MiB is held in memory and larger uploads spool to a temp file. The body is capped at FILE_SIZE_LIMIT + 1 MiB. | PutObject needs a seekable, known-length body to sign |
| Storage not configured | boto3 fails while presigning (500) | The server starts without storage (a warning is logged). Asset endpoints that need the bucket answer 503 "File storage is not configured." | Running without storage is allowed by design |
